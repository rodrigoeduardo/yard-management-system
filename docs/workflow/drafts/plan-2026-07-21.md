# Plan 2026-07-21 — Test-suite speed & CI restructure

Source: profiling session on `npm test` (2026-07-21). Findings: full suite = 108 files / 700 tests,
~82s wall locally, 141s in CI (of ~187s total job time). 19 DB-integration test files
(`lib/db/**`, `lib/actions/**`, `lib/supabase/**`, auth actions, seed script) account for ~92% of
aggregate test time (~292s of 317s) because every query pays a network round-trip to the remote
Supabase project. All component/jsdom + pure unit files together finish in ~10s wall.

CI triggers are already PR-only (`push: branches: [main]` + `pull_request`) — no change needed there.

Created as issues #235 (split), #236 (ci.yml), #237 (local Supabase).

| # | Title | Area | Depends on | Acceptance criteria (summary) | Human actions |
|---|---|---|---|---|---|
| 1 | [setup] Split vitest suite into unit/component/integration projects | setup | None | `vitest.config.ts` gains an `integration` project matching all DB/network-touching test files (`lib/db/**`, `lib/actions/**`, `lib/supabase/**`, `app/login/actions.test.ts`, `app/register/actions.test.ts`, `scripts/lib/seed-demo-data.test.ts`); `npm test` runs only unit+component and needs no DB env (< ~15s); `npm run test:integration` runs only DB files; `npm run test:all` runs everything and equals today's coverage (700 tests); `.claude/agents/auto-executor.md` green-gate updated from `npm test` to `npm run test:all` | None |

| 3 | [setup] Run integration tests against local Supabase (CLI/Docker) | setup | #1 | `supabase start`-based local stack (or docker-compose equivalent) usable by `npm run test:integration` locally and in CI; migrations + test user seeded automatically; integration suite passes without any remote-project secrets; CI integration job no longer touches the shared remote DB (kills cross-run interference documented in auto-next-task SKILL); wall time of integration job drops materially vs. baseline | Confirm Docker is available on the dev machine; decide whether remote-DB secrets stay for any job |

Notes:

- Task 1 is the fast win: every local TDD loop drops from ~82s to ~10s.
- Task 2 without task 1 gains little — `npm test` is 141s of the 187s job; splitting jobs only pays
  once the fast path excludes integration files.
- Task 3 is the structural fix: removes remote round-trip latency (~292s aggregate → seconds) and the
  shared-remote-DB interference hazard between concurrent CI runs / local runs
  (`.claude/skills/auto-next-task/SKILL.md:131`). Bigger setup cost, hence separate and last.
