# Plan Board draft — 2026-07-17 (UX / navigation focus)

Focus per request: **user experience, not styling**. What each page *displays*, which pages
are missing, modals to expand information, and a **full navigation cycle** — no dead ends,
breadcrumbs where nesting warrants them. All issues are `status:proposed` until the human
promotes them.

## Problem statement (current nav reality)

| Page | Displays | Dead end? |
|---|---|---|
| `/` (home) | Title + "Aplicação em construção" + Sair | **Yes** — no link to any feature |
| `/login` | Login form | n/a |
| `/inventory` | Stock table + removal-log table | **Yes** — rows not clickable, no nav, no home link |
| `/loads/new` | Add-load form → redirects to print | No back nav |
| `/loads/[id]/print` | QR grid + print button | **Yes** — nothing after printing |
| `/removals/new` | Removal form + scanner → total weight inline | **Yes** — no nav after completion; can't drop a mis-scanned item |

Root cause: `layout.tsx` renders only `{children}` — there is no app shell/header. Every
feature was built vertically with no cross-linking. Item `status` (`in_stock`/`removed`)
exists in the data model but is surfaced in **no** UI.

## Notes / decisions

- **Modals vs pages**: expansions use modals (per request) rather than new deep-linked
  detail pages, avoiding a `/loads/[id]` page that would duplicate the print route + modal.
  If a deep-linkable load page is later wanted, it's a clean follow-up.
- **Testing**: modal open/close and scan-list edits follow the repo's established pattern
  (extract pure logic → unit test; manually verify the rendered component) since component
  test infra (#39, `status:proposed`) is not yet ready. #39 would let these add interaction
  tests — noted, not a hard dependency.
- **No styling scope**: every issue is about *what is shown* and *reachability*, not visual
  design. Layout classes reuse existing Tailwind conventions already in the pages.
- **No conflicts** with open issues #35–#42. #42 ("distinct load field in the removal
  scanned-item list") is adjacent to #6/#9 but distinct (it concerns the live scan list
  label, not the modals) — left as-is.

## Out of scope (deliberately deferred)

- Search/filter on inventory tables (business-rules marks tables read-only; filtering is a
  separate UX concern, propose later if wanted).
- Editing/voiding a load or removal (no spec for mutation-after-the-fact).
- Any visual redesign, theming, responsive/mobile-specific work.
