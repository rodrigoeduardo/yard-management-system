# Plan 2026-07-22 — Product pivot: generic demo yms + private client fork (patio)

Source: grilling session on the SaaS-ification goals (not spec deltas). Decisions recorded in ADRs 0001–0003 (`docs/adr/`), written in the same session.

Decision summary:

- **Fork model** (ADR 0001): `patio` = private duplicate of yms with full history + `upstream` remote; updates via manual `git merge upstream/main`; config-first customization; yms stays private for now (license deferred).
- **Demo mode** (ADR 0002): `DEMO_MODE` env flag; all auth code retained; auto-session as one seeded demo user; `/login` + `/register` redirect; persistent PT-BR demo banner with contact CTA. Current Supabase project (dev data only) serves the demo; client gets own project at go-live.
- **Demo hygiene** (ADR 0003): nightly pg_cron reset — truncate domain tables + `audit_log`, reseed realistic sample data; scheduling applied only on the demo project (fork-safe); no write caps for now.
- **Landing page**: separate repo (human builds with Claude Design); tracked on this board under a new `area:landing` label; Contact Us delivers via an email service (e.g. Resend/Formspree free tier); CTA links to the demo URL.
- **Hosting**: Vercel Hobby for demo + landing now (ToS risk accepted), VPS/Coolify later.

## Findings / conflicts to flag

- **Specs contradict demo direction**: `architecture.md` (Auth bullet) and `business-rules.md` (Registration section) describe invite-gated signup as the only mode. Proposal #1 updates them to document `DEMO_MODE` alongside.
- **Fork-safety invariant** (new, from ADR 0001): migrations and shared code flow yms → patio on every merge, so demo-only behavior must be inert unless explicitly enabled. Affects #4 (flag off by default) and #7 (reset job defined but not scheduled by migration).
- **Vercel Hobby ToS**: lead-gen demo is arguably commercial use. Accepted knowingly; `architecture.md` already lists VPS+Coolify as the alternative.
- **PR-note follow-up** (auto-configure PR): label creation should be idempotent/explicit — #1 creates the two new labels with `gh label create`, which covers it for these labels.
- **Landing page tasks run outside the yms builder flow**: the board tracks them (Projects v2 handles cross-repo/draft items), but `/next-task` builders operate in this repo only — #9 is human-driven.
- No open issues on the board today; no duplicates possible.
