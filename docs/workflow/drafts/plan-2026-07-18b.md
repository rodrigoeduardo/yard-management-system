# Plan draft — Post-usage feedback batch: auth, timing fields, layout & scan UX — 2026-07-18 (b)

Source: human feedback after using the app (8 items). Delta run — prior batch today (`plan-2026-07-18.md`, issues #91–#103) is fully merged; board has zero open issues, so no duplicates or conflicts.

## Decisions (locked by human, 2026-07-18)

1. **Registration gating** → invite code: register page requires a secret code (env var `REGISTER_INVITE_CODE`); no admin UI, no approval queue. Rotating the code revokes signup access.

## Implementation facts (verified in code)

- Only `/login` exists (`PUBLIC_PATHS = ["/login"]` in `lib/supabase/middleware.ts`); no signup function anywhere. Login server action in `app/login/actions.ts`; Zod credentials schema in `lib/auth/credentials-schema.ts`; display-name convention `user_metadata.display_name` (PR #107).
- Login page (`app/login/page.tsx`) has plain `<h1>Entrar</h1>` — no logo, no "Pátio" title. Desktop top nav (`components/nav/top-nav.tsx`) already has a logo block to mirror.
- No theme library and no functional dark mode. Only a non-functional `Moon` placeholder button in `components/home/mobile-header.tsx`, plus a dead `.dark {…}` token block and `@custom-variant dark` in `app/globals.css` that nothing activates.
- `removals.exit_date` is already `timestamptz` (`lib/db/schema.ts`) — exit-time capture needs **no migration**. Nova Remoção form (`app/(authenticated)/removals/new/page.tsx`) captures date only. Reusable pattern: Nova Carga's `entryTime` + `combineEntryDateTime` (`lib/loads/entry-datetime.ts`), yard timezone pinned in `lib/format/datetime.ts`.
- Última Movimentação card (`components/home/last-movement-card.tsx`) shows date+time for the load row (`formatEntryDateTime`) but date-only for the removal row (`formatYardDate`).
- Nova Carga desktop weights summary (`app/(authenticated)/loads/new/page.tsx` ~394–421) is one flex row: Peso Restante · Peso da NF · helper text · submit (`ml-auto`). Mobile has its own fixed-bottom summary.
- `useTopLoaderTask(active)` exists (`components/ui/top-loader.tsx`) but neither the create-load nor the remove-items `useTransition` submit wires it — the global bar never animates for those actions; buttons only turn disabled.
- Scanner (`@zxing/browser`, continuous decode) has a per-token in-flight lock (`pendingTokensRef`) but **no time-based cooldown**: the camera re-reads the same code within milliseconds, producing an immediate "already scanned" error after every successful scan.
- Tests: Vitest (node + jsdom projects), colocated `.test.ts(x)`, Testing Library.
