# Plan draft — Restyle follow-ups: UX fixes + per-screen pixel-fidelity — 2026-07-18

Source: human review of the merged restyle batch (PRs #80–#90) against the design handoff, now checked in at `docs/ui/design.html` + `docs/ui/README.md`. Two workstreams: (1) eight concrete UX fixes reported by the human; (2) a per-screen pixel-fidelity pass, since the restyle "was not completely loyal to the design doc". **Mobile-first** throughout, per the handoff.

## Decisions (locked by human, 2026-07-18)

1. **Display name** → Supabase auth `user_metadata.display_name`, set manually in the Supabase dashboard (no in-app settings UI). Email-derived name stays as fallback.
2. **Entry time** → store in the existing `loads.entry_date` timestamptz (no migration) **and show date+time everywhere** entry date is displayed.
3. **Fidelity work** → per-screen fix issues (one builder session each), not one mega-audit.

## Implementation facts (verified in code)

- No `loading.tsx` anywhere, no loader/spinner primitive; login is a server-action form + `redirect` (`app/login/actions.ts`). App Router has no router events — use `useLinkStatus`/`onNavigate` (Next 15.3+) or equivalent + `useFormStatus` for form submits.
- `loads.entryDate` is **already timestamptz** (`lib/db/schema.ts`); date-only form strings currently coerce to midnight UTC via `z.coerce.date()` in `lib/actions/loads.ts`.
- "Continuar para pesos" (`app/(authenticated)/loads/new/page.tsx:357-366`) advances unconditionally — no gating.
- Print: `TopNav`/`BottomTabBar` are not `print:hidden`; zero `@media print`/`@page` rules repo-wide; only Tailwind `print:` utilities inside `components/loads/qr-print-view.tsx`.
- `getUserDisplayName` (`lib/auth/user-display-name.ts`) + `getUserInitials` derive purely from the email local-part; nothing reads `user_metadata`.
- Shared `Input` (`components/ui/input.tsx`) passes `placeholder` through natively — callers just never set it. Login page uses raw `<input>`s, not the shared primitive.
- `getLastRemoval` (`lib/db/dashboard.ts`) powers the Última Movimentação card; no last-load query exists.
- Weight inputs are `type="number"` (native spinner arrows), full-width cells in `grid-cols-2 md:grid-cols-4`.

No existing open issue conflicts (open: #35/#37/#38 are CI/deploy/auth-advisors, unrelated). No duplicates.

## Build convention (applies to every issue)

Unprefixed Tailwind classes are the mobile (390px) layout; desktop layered via `md:`/`lg:`. Fidelity issues (H–M) assert **pixel-perfect at the two reference viewports (390px / 1280px)** against the matching `data-screen-label` frame in `docs/ui/design.html`: spacing, dimensions, radii, colors (via the token names from `globals.css`, not raw oklch), font family/size/weight, and copy. PRs attach before/after screenshots at both widths. Dark-mode frames in the design file are out of scope (README: light mode only).
